# BB-006 completion evidence

**Result:** Passed for the durable, local research-job boundary and one-worker lifecycle.

**Evidence type:** Synthetic requests, temporary local SQLite/artifact storage, deliberate process failure, and a fresh non-editable installed-package demonstration. This story has no broker, market-data provider, LLM, or browser integration, and none was contacted.

**Base revision:** `9b739fa726219fd82418faac16ae572143414455` (implementation changes were verified in the working tree before commit).

## Delivered behavior

| Acceptance criterion | Implementation and verification |
| --- | --- |
| Durable identity and state | Strict versioned requests require UUID request/run IDs and permit only the harmless `research_probe` kind. Requests persist queued/running/succeeded/failed/interrupted/cancelled states, timestamps, progress, artifacts and events. Repeated identical request IDs are idempotent; changed meanings are rejected. |
| Transactional state | Claims and updates use short `BEGIN IMMEDIATE` transactions. Locked SQLite writes retry after 50 ms and 100 ms, then report busy. Tests hold an exclusive database transaction and confirm no partial submitted job. |
| Migration safety | SQLite migrations are numbered, run inside an explicit migration transaction, and advance `user_version` together with schema changes. Existing databases are backed up before upgrade. Newer schemas and inconsistent markers are rejected; a deliberately failing migration leaves no new table or schema version. |
| Honest recovery | Startup converts persisted running research jobs to `interrupted` with `worker_restarted`; it never requeues or repeats them. Generic jobs cannot express broker work, so broker-command retry is absent by construction. |
| Artifact-before-success | Result and diagnostic JSON are written through a staging file, fsynced, renamed, directory-fsynced, reread and hashed. Only a verified result can transition to succeeded. A forced publication failure leaves a diagnostic/failed record rather than a false success. |
| Single worker and child boundary | The worker owns an OS file lock for its run. A second process is denied; killing the owner releases the lock and a replacement marks abandoned work interrupted. The child is spawned without the lock descriptor or broker environment. One child is allowed, with 35-second wall-clock and 30-second CPU limits. |
| Local control surface | JSON CLI commands submit, inspect, cancel, and list jobs; inspect status; run once/serve; and persist shutdown/resume. The shutdown flag prevents new claims, causes an active child to stop, and is not cleared by process restart. These operations do not require an LLM or browser. |

## Verification

```bash
uv run --locked --offline --group qualification ruff check src tests qualification examples
uv run --locked --offline --group qualification ruff format --check src tests qualification examples
uv run --locked --offline --group qualification pytest -q tests/test_jobs.py
uv run --locked --offline python examples/jobs/validate.py
uv run --locked --offline --group qualification pytest -q
uv pip check
git diff --check
```

All commands passed. The focused suite has 15 tests covering duplicate requests, transactional claims, bounded contention, cancellation, restart handling, invalid transitions, migration backup/newer/inconsistent/failed schemas, secret-free result publication, publication failure, timeout, lock ownership/release, parent death, persisted shutdown, and socket-disabled CLI behavior. The complete suite has 272 passing tests; Ruff reports 41 formatted Python files and `uv pip check` reports all 275 installed packages compatible.

The offline example emits a succeeded synthetic job with three durable events (`queued`, `running`, `succeeded`), a hash-verified `result.json`, and temporary storage removal. It replaces Python socket/DNS access with failures before importing the package and confirms that Lumibot, Alpaca, and scikit-learn are not imported.

A separate temporary environment was created using:

```bash
UV_PROJECT_ENVIRONMENT=/tmp/buffetbot-fresh-verify-<pid>/venv \
  uv sync --locked --offline --no-editable --reinstall-package buffetbot --group qualification
```

From `/tmp`, the installed wheel ran `examples/jobs/validate.py` successfully. The final import resolved to that environment's `site-packages/buffetbot/__init__.py`, rather than the repository's `src/` directory.

## Scope boundary and handoff

The [job guide](../../jobs.md) documents the CLI and on-disk contract. BB-006 intentionally contains no order handler, broker client, data import handler, LLM call, dashboard, or automatic retry/resume. Later stories must add only explicit, validated job handlers and retain the durable request/event/artifact boundary. Paper order lifecycle work must reconcile its own intent and broker state rather than inheriting generic research retry.
