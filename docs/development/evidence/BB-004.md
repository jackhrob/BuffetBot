# BB-004 completion evidence

**Result:** Passed for immutable market snapshots, quality validation and offline fixtures.

**Evidence type:** Synthetic local records, deliberate filesystem/process failures, the existing engine regression and a fresh wheel installation. No actual market history, broker account or model service was used for this story.

[BB-004-verification.json](BB-004-verification.json) records the verification time, base Git revision, source/fixture/dependency hashes, commands/results and fresh-environment output. [BB-004-quality-reports.json](BB-004-quality-reports.json) retains the complete accounting manifest/report, positive and rejected fixture reports, publication commands and matching inspection result. Earlier story evidence remains historical.

## Delivered behavior

| Acceptance criterion | Implementation and verification |
| --- | --- |
| Atomic immutable publication | Validate, write/fsync staging files, verify through the reader, then rename/fsync the local directory. Identical concurrent imports converge; revised records produce a new ID without changing the previous files or modification times. Forced process exits after the first Parquet write and immediately before rename leave only unusable staging directories; retry succeeds. |
| Complete manifest | Canonical manifest hashes all three Parquet files and declares schema, origin, provider/feed, universe/listing, coverage/warmup, retrieval/availability/revisions, adjustments, action source/completeness, calendar, zero-volume policy, counts and quality findings. Source rows are bound to the resulting dataset ID on verified read, avoiding a hash cycle. |
| Reusable quality checks | Ordered unique observations/actions, finite exact OHLC/volume units, valid OHLC ranges, listing/warmup coverage, session boundaries, retrieval timing and matching provenance are validated. Invalid rows and inconsistent metadata produce recoverable errors. Zero volume follows an explicit allow-with-warning/reject policy. |
| Calendar and missing data | One pinned NYSE calendar distinguishes July 4/weekend closures from missing July 5 data; July 3 retains its shortened close. A separate fixture test verifies New York session hours across the November DST transition. No missing or pre-listing bars are fabricated. |
| Raw prices, research views and actions | Raw executable prices remain unchanged. Research views adjust only for effective, available splits within declared action coverage. Split ratios and cash-dividend ex/pay dates are explicit; unsupported actions and unknown completeness block publication. Experiment binding validates exact reference, instrument/listing, range and warmup. |
| Offline cases and independent expectations | Packaged accounting, missing-bar, gap, zero-volume and incomplete-action cases work without an account. The six-session accounting input retains BB-002's qualified prices/actions. An independently authored post-event ledger and arithmetic are retained in the [fixture notes](../../../src/buffetbot/fixtures/README.md). Application ledger execution remains BB-009. |
| Explicit origin | Origin is required on plans and raw bars, preserved on manifests, quality/inspection reports, research views and dataset references. Mixed origin is rejected. Missing/invalid read identity is explicitly unverified. Synthetic metadata cannot silently become a historical report. |
| Verified reads | Missing/corrupt/extra/symlinked files, unsupported versions/counts and changed manifest metadata/quality are rejected. Reader checksums and decodes the same bytes, then revalidates quality. DuckDB queries the verified in-memory records through the shared report path. Reimport refuses to overwrite or repair damaged referenced versions. |

## Verification results

```bash
uv run --locked --offline --group qualification pytest -q
uv run --locked --offline --group qualification ruff check src tests qualification examples/contracts/validate.py
uv run --locked --offline --group qualification ruff format --check src tests qualification examples/contracts/validate.py
uv pip check
git diff --check
```

**Passed:** 199 tests in 35.66 seconds, including 49 snapshot cases and all 150 prior cases. Ruff lint passed and all 27 Python files were formatted. All 275 installed packages in the qualification environment were compatible. The Python socket/DNS-disabled CLI test publishes, inspects and rejects fixtures without importing Lumibot, Alpaca or scikit-learn.

A second fresh temporary environment used `uv sync --locked --offline --no-editable`. From outside the repository, its installed CLI published the packaged fixture and ran the doctor. An import check confirmed the package came from the installed wheel, fixture resources were present, and Lumibot/scikit-learn were absent. All four commands returned zero; the temporary environment was removed after recording results.

The default fixture reproduces dataset ID:

```text
39138d9233ad4dc29ce1355a24f4c64aa0a4843f529ec0f91b49e1cb7882eba9
```

It contains six bars, one 2-for-1 split, one regular cash dividend and six exchange sessions. Publication and inspection return matching JSON. The gap and zero-volume variants publish with explicit warnings; missing-bar and incomplete-action variants return exit 1 with their quality reports and no published snapshot.

Three existing locked qualification dependencies become direct runtime requirements for their concrete storage functions: DuckDB 1.5.5 for inspection, PyArrow 25.0.1 for exact Parquet serialization, and pandas-market-calendars 5.4.0 for the selected exchange schedule. No dependency versions changed, and no server, catalog or trading engine was added to the default runtime. The shared BB-003 contract example still passes without importing these storage libraries.

## Handoff

See the [dataset guide](../../datasets.md) for commands and the public storage/read/binding functions. BB-005 should pass normalized records and substantiated source metadata to this publisher. A provider must establish full action coverage, explicitly choose its feed and qualify its bar/revision/availability semantics; the publisher cannot independently discover omitted corporate actions or verify a source's truthfulness.

The storage implementation handles small local daily ETF datasets in memory. It does not implement provider downloads, job persistence, strategy formulas, feature computation, application accounting, reports of strategy performance or broker connectivity. BB-009 must still run and reconcile the application ledger against the authored fixture outcomes. Only the immutable-data release row advances; the full MVP and actual external integrations remain incomplete.
