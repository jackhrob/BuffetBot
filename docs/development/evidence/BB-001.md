## Verification method

The repository has no commits yet, so clean-install verification used a fresh temporary copy of the public project files, source, tests, example configurations, and runtime README. It did not copy the existing virtual environment, private configurations, runtime state, or Python caches. A new environment was created from the lockfile.

Credential variables, inherited virtual-environment settings, and `PYTHONPATH` were removed from the verification environment. Checks confirmed both the isolated interpreter prefix and that imports came from the fresh source copy. After initial provisioning, commands used uv's offline mode. The doctor did not create runtime directories in that copy.

The executed command sequence is preserved in the JSON evidence. Its essential commands, run from the clean project root, were:

```bash
uv sync --locked
uv run --locked --offline buffetbot --version
uv run --locked --offline buffetbot doctor --json
uv run --locked --offline buffetbot doctor --config config/paper.toml --json
uv run --locked --offline buffetbot doctor --config config/paper.toml --require-broker --json
uv run --locked --offline ruff check src tests
uv run --locked --offline ruff format --check src tests
uv run --locked --offline pytest -q
```

The required-broker check intentionally returned **1**, demonstrating the missing-prerequisite behavior. All other commands above returned **0**. The suite includes invalid mode/endpoint/path cases, explicit credential loading and precedence, dummy secrets in output/errors/exceptions, and an invocation with socket construction disabled to detect attempted network use.

The temporary verification copy was removed after recording evidence. The JSON records a content hash of the delivered Python/configuration/test/lock files instead of claiming a nonexistent Git commit.

## Limits and next story

This evidence verifies BB-001 only. Configuration presence does not authenticate credentials. The doctor is not a trading-readiness check; it runs no strategy, broker order, market download, model inference, database, worker, or dashboard. Directory permission checks describe the current filesystem and do not guarantee a later write succeeds.
